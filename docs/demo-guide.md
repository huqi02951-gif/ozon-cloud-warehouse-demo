# 四个演示场景

开始前，以管理员角色进入“系统设置”，点击“重置演示数据”及「确认重置」，顶部选择全部店铺、全部云仓。所有数据和接口均为本地模拟，刷新保留当前浏览器 localStorage 数据。

## 场景 一：正常订单完整履约

1. “订单中心”打开“正常履约演示单”（`order-normal`），点击「获取面单并下发云仓」。共享流程先生成带 DEMO / 演示数据 水印的面单，再交给模拟云仓并锁定库存。
2. “出库履约”找到同一订单，依次点击“推进至拣货中”“推进至已打包”“推进至已出库”“推进至待同步 Ozon”“推进至已完成”。
3. “库存中心”核对发货时在库数量扣减、锁定数量释放，可用库存不会重复扣减。“订单中心”核对最终平台状态 delivered，唯一出库任务成功。“异常与日志”查看全过程操作日志。
4. “面单中心”可预览、模拟打印面单；所有标签带演示水印。

## 场景 二：主仓缺货自动改派

1. “缺货改仓演示单”（`order-fallback`）的优先仓可售库存不足。在“出库履约”找到该订单，点击“自动路由并下发云仓”。
2. 系统选择有库存的备用云仓，生成面单并创建唯一出库任务。订单变为云仓已接单，只锁定实际承接仓库存。
3. 订单详情核对指派仓库，库存及操作日志核对改派结果。重复下发不会创建第二个任务或再次锁定库存。

## 场景 三：修复 SKU 映射并重试

1. “SKU 未映射演示单”（`order-unmapped`）初始处于映射异常；进入“SKU 映射”，筛选缺失映射，点击对应 SKU 的“建立映射”。
2. 选择云仓货号后点击「保存并重试」。全部映射修复后，关联的 `task-sync-unmapped` 异常被解决，并重新获取面单、路由和下发。
3. “出库履约”核对 `order-unmapped` 已接单，“异常与日志”核对对应失败项消失，原始错误及修复日志仍可追溯。

## 场景 四：rFBS 退货恢复可售库存

1. “rFBS 退货”打开 `return-01`（关联“rFBS 退货演示单” `order-return`），选择“退回云仓”，点击“同意退货”和“确认同意”。
2. 再次打开退货，点击“确认签收”，随后点击「验货：恢复可售」。
3. “库存中心”核对所选退货仓在库与可用库存各增加 1；收货任务完成，重复验货不会重复入库。“异常与日志”查看审核、签收及验货记录。

## 补充操作

“订单中心”点击“模拟拉取新订单”，打开待校验订单后点击“校验并继续分仓”，再获取面单并下发。发货前取消已接单订单会释放该订单锁定库存并取消出库任务，发货后不支持取消。

顶部切换角色及筛选范围可查看权限差异，仓库人员库存只读。设置保存在本机，确认重置恢复初始值。暂不包含商品创建/图片上传、订单部分取消、真实 Ozon 或云仓连接，也不表示与生产系统全部功能一致。
