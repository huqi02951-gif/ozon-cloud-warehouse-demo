# Ozon 多店铺云仓运营中台 Demo 设计规格

## 1. 项目目标

建设一套可点击、可连续演示的中文 Web Demo。系统业务能力对齐 Ozon Seller 的订单、面单、商品、库存、价格和 rFBS 退货管理，同时增加多云仓履约能力。

Demo 用于确认产品方向、演示核心业务闭环和辅助开发工作量评估，不连接真实 Ozon 或云仓 API，不处理真实订单、面单或库存。

## 2. 已确认的产品边界

- 支持多个 Ozon 店铺统一管理。
- 支持 FBS 与 rFBS 场景。
- 支持多个云仓及订单自动分仓。
- 系统从 Ozon 获取面单，并随出库任务下发云仓打印。
- Ozon 可售库存以云仓回传库存为数据源。
- 系统是卖家运营与云仓履约中台，不建设库位、波次、PDA、盘点等完整 WMS 能力。
- 角色包括管理员、运营人员、仓库人员。
- 全部业务数据均为虚构演示数据，面单带“演示数据”水印。

## 3. 核心业务闭环

### 3.1 正常履约

1. 从 Ozon 模拟拉取新订单。
2. 校验店铺、SKU 映射、仓库能力和可用库存。
3. 按路由规则自动选择云仓。
4. 从 Ozon 模拟获取面单。
5. 生成唯一出库任务并下发云仓。
6. 云仓依次回传已接单、拣货中、已打包、已出库。
7. 系统模拟向 Ozon 确认发货。
8. 更新订单状态、工作台指标、库存和操作日志。

### 3.2 缺货改仓

1. 首选仓可用库存不足。
2. 系统按规则查找备用仓。
3. 有货时自动改派；无货时进入异常中心。
4. 运营人员可手工选择仓库并重新校验。

### 3.3 SKU 映射异常

1. Ozon SKU 未匹配云仓货号。
2. 订单停止下发并进入异常中心。
3. 运营人员建立映射。
4. 一键重试后继续原履约流程，不重复创建出库任务。

### 3.4 rFBS 退货

1. 查看退货申请、商品、原因、图片和物流节点。
2. 运营人员执行同意或拒绝。
3. 同意后选择退回云仓。
4. 模拟云仓签收、验货和结果回传。
5. 更新退货状态、库存状态和操作日志。

| 页面 | 主要内容 | Demo 交互深度 |
| --- | --- | --- |
| 运营工作台 | 店铺汇总、待发货、截单预警、缺货、异常、退货 | 深度 |
| 订单中心 | 拉取、筛选、详情、取消、批量操作、状态时间线 | 深度 |
| 出库履约 | 自动分仓、手工改仓、下发云仓、仓库处理进度 | 深度 |
| 面单中心 | 获取 Ozon 面单、预览、批量下发、打印状态 | 深度 |
| 商品中心 | 商品列表、详情、图片、上下架和同步状态 | 基础 |
| 库存中心 | 多仓库存、占用、可用、残次、安全库存、同步结果 | 深度 |
| 价格管理 | 当前价、促销价、批量改价和结果状态 | 基础 |
| rFBS 退货 | 申请详情、原因、物流、审核和收货结果 | 深度 |
| 云仓管理 | 云仓档案、连接状态、仓库能力和覆盖区域 | 深度 |

## 5. 页面与交互设计

### 5.1 全局框架

- 左侧固定导航，按“经营、履约、商品、配置”分组。
- 顶部提供店铺、云仓和角色切换。
- 支持“全部店铺”汇总视图。
- 状态使用颜色标签，危险操作需要二次确认。
- 关键动作显示加载、成功或失败反馈。
- 操作后关联页面同步变化，不采用静态跳转假交互。

### 5.2 订单详情

订单详情采用抽屉或独立详情页，包含：订单信息、商品明细、收件信息脱敏展示、云仓履约、状态时间线、接口记录。可执行分仓、取消、获取面单、下发云仓和重试。

### 5.3 面单

面单支持单张预览、批量生成和打印演示。模拟条码不得代表真实 Ozon 面单，预览区域必须展示“DEMO / 演示数据”水印。

### 5.4 库存

- 展示实物库存、占用库存、可用库存、残次库存和在途库存。
- Ozon 同步量 = 云仓可用库存 - 安全库存，最低为零。
- 支持单个修改安全库存和批量同步演示。
- 库存不足时禁止出库任务继续下发。

### 5.5 自动分仓规则

Demo 使用以下确定性顺序：

1. 店铺指定仓库。
2. 配送区域覆盖。
3. SKU 可用库存充足。
4. 优先级数值较小的仓库。
5. 若仍有多个仓库，选择预计处理时长较短者。

Demo 不实现运费优化、拆单优化或机器学习分仓。

## 6. 角色权限

| 能力 | 管理员 | 运营人员 | 仓库人员 |
| --- | --- | --- | --- |
| 店铺、云仓、权限配置 | 可操作 | 只读 | 不可见 |
| 订单与取消 | 可操作 | 可操作 | 只读 |
| 分仓与异常重试 | 可操作 | 可操作 | 只读 |
| 面单与出库 | 可操作 | 可操作 | 可操作 |
| 商品、库存、价格 | 可操作 | 可操作 | 库存只读 |
| rFBS 退货 | 可操作 | 可操作 | 收货状态可操作 |
| 接口与操作日志 | 可查看 | 可查看 | 仅相关任务 |

## 7. 演示数据

- 3 个虚构 Ozon 店铺。
- 3 个虚构俄罗斯云仓。
- 50 个商品 SKU。
- 30 笔覆盖主要状态的订单。
- 4 笔重点演示订单：正常履约、缺货改仓、SKU 未映射、rFBS 退货。
- 金额使用卢布符号，日期时间明确显示时区。
- 不使用真实客户姓名、电话、地址、密钥或物流单号。

## 8. 状态模型

系统统一履约状态为：已拉取、待校验、待分仓、待下发、云仓已接单、拣货中、已打包、已出库、待同步 Ozon、已完成、已取消、异常。

平台原始状态和云仓原始状态分别保留，统一状态只用于系统内部展示和流程判断。

## 9. 接口边界

### 9.1 Ozon 适配器

负责店铺鉴权、订单拉取、订单详情、订单取消、面单获取、发货确认、商品查询、库存同步、价格同步和 rFBS 退货数据。Demo 以本地模拟服务替代。

### 9.2 通用云仓适配器

负责云仓档案、库存查询、出库单创建、出库单取消、面单文件下发、履约状态查询或回调、运单回传和退货入库结果。具体云仓接口文档取得后仅替换适配层映射。

### 9.3 幂等与任务记录

- 每笔外部写操作生成唯一任务号。
- 相同业务对象与动作不得重复创建有效任务。
- 每次请求记录时间、对象、状态、重试次数和脱敏摘要。
- Demo 模拟接口延迟、失败与重试，不存放密钥。

## 10. 异常处理

Demo 至少覆盖：Ozon 超时或限流、云仓调用失败、重复下发、云仓拒单、SKU 未映射、库存不足、面单失败、云仓已出库但 Ozon 未更新。

异常必须给出：业务对象、失败节点、可理解原因、建议动作、最近一次尝试时间和重试按钮。不可重试的业务错误需要先修复数据或规则。

## 11. 技术与运行形式

- 交付为可在浏览器打开的前端 Demo。
- 默认桌面端，重点适配 1366×768 和 1440×900。
- 全部模拟数据内置，首次打开即可使用。
- 操作状态在刷新后可恢复，提供“重置演示数据”功能。
- 不依赖真实 API、数据库、登录服务或云仓账号。
- 代码结构预留 Ozon 适配器与云仓适配器接口，但 Demo 不发送真实外部请求。

## 12. 视觉规范

- 中文运营后台，保持高密度但清晰的数据表格体验。
- 白色背景、蓝紫主色、浅灰分区；成功、预警、危险使用统一语义色。
- 视觉语言参考 Ozon Seller 的专业运营感，但不复制其商标、受保护图形和页面源代码。
- 俄文或英文原始状态旁提供中文释义。
- 图表仅用于工作台关键指标，不用装饰性大屏效果。

## 13. 验收标准

1. 12 个页面均可从导航访问，无空白页和死链接。
2. 4 条重点演示流程均可从初始数据连续完成。
3. 正常出库后订单、库存、工作台和日志同时更新。
4. SKU 未映射订单无法下发，补充映射后可重试成功。
5. 首选仓缺货时可自动选择符合规则的备用仓。
6. 重复点击下发不会产生两个有效出库任务。
7. 三类角色看到的导航与操作权限不同。
8. 面单预览带明显演示水印。
9. 页面刷新后保留当前演示状态，并可一键重置。
10. 在 1366×768 和 1440×900 下无关键遮挡或横向溢出。

## 14. 非目标

- 不接入真实 Ozon 或云仓账号。
- 不实现真实支付、退款或财务结算。
- 不建设完整 WMS、采购管理、入库上架、库位和盘点。
- 不实现多电商平台接入。
- 不实现智能预测、运费优化或经营决策模型。
- 不宣称 Demo 数据或结果可用于生产。
