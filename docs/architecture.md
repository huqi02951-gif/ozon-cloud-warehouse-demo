# 架构说明

应用是 Vite + React + TypeScript 单页应用。Hash 路由避免 GitHub Pages 对深层路径的回源要求；`base: './'` 让静态资源可从项目子路径加载。`DemoProvider` 统一承载固定初始数据、角色、命令执行、提示消息和 `localStorage` 恢复，领域 reducer 保证订单、任务、库存、退货与日志联动。Ozon 与云仓 adapter 只返回确定的模拟结果，不发起网络请求。

## 决策记录

- 依赖使用精确版本；升级时必须同时更新并提交 lockfile，避免演示环境漂移。
- 商品视觉使用虚构渐变和首字母，降低了照片真实感，同时避免使用真实品牌素材。
- 自动路由校验库存、连接状态与仓库能力；显式手工改仓增加了一个操作字段，并在下发前执行同样校验。
- 价格以整数卢布保存，最小值为 1；若以后支持戈比，需要迁移金额模型、输入校验和格式化逻辑。
- Provider 接受可选 `initialState` 与 `initialRole`，用于确定性场景测试和权限测试。
- 当前无数据库，状态只写入当前浏览器 `localStorage`。真实多租户必须把身份、授权、持久化、审计和并发控制放到后端。

## 生产迁移边界

真实系统需要服务端鉴权和按租户授权，并以持久化数据库与作业队列取代浏览器状态。Ozon API 与各云仓协议应通过服务端 Ozon adapter、云仓 adapter 接入，统一处理凭据、限流、幂等、重试与可观测性。前端不能持有生产凭据，也不能以当前角色选择器代替授权。
