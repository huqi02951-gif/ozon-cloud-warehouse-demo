# 需求与范围

## 目标

用一套可重复的虚构数据演示多店铺、多云仓的运营协作。12 个路由均提供可阅读内容和有意义的查看或操作入口；顶部“当前店铺”“当前云仓”会收窄各页面数据，系统设置中的“重置演示数据”可恢复初始状态。

## 角色

| 角色 | 主要能力 |
| --- | --- |
| 管理员 | 查看全部模块，操作业务流程，配置仓库、授权和系统设置 |
| 运营人员 | 操作订单、履约、商品、价格、退货和映射；仓库与设置为只读 |
| 仓库人员 | 查看工作台、订单、库存和异常；推进出库与处理退货；不显示商品、价格及配置模块 |

角色与可见性仅在前端模拟，不能作为真实权限控制。

## 已实现

- 固定虚构数据下的订单检索、分仓校验、批量/单笔下发及履约状态推进。
- 面单批量获取、预览和模拟打印；面单带有“DEMO / 演示数据”水印。
- 商品浏览、库存安全量调整与同步模拟、批量调价。
- rFBS 退货审核、选仓、签收、可售/残次验货及库存、日志联动。
- SKU 映射单笔修复和批量导入预览，修复后重试受阻订单。
- 异常任务、操作日志、云仓配置、店铺授权、同步设置及确认重置。
- 店铺/云仓筛选与浏览器本地持久化。

## 延后

- 商品创建和图片上传。
- 订单部分取消及取消后的金额、库存、履约拆分。
- 真实 Ozon、云仓、物流、身份认证、审计和数据库集成。
- 多租户并发、服务端幂等、后台任务、监控告警和正式报表。

这些延后项不应在演示中被描述为已交付。
